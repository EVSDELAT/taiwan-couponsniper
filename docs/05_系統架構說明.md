# 系統架構與資料流說明

## 一、資料來源

目前整合兩個公開來源：

1. Uber Eats：<https://raw.githubusercontent.com/ridemountainpig/tasty-coupon/main/coupon-json/ubereats-coupon.json>
2. foodpanda：<https://raw.githubusercontent.com/ridemountainpig/tasty-coupon/main/coupon-json/foodpanda-coupon.json>

ChatGPT Site 的 Worker 另外會讀取以下文章頁，取得文章更新日期及較完整的表格內容；如果文章表格無法解析，才回退到上述 JSON：

- <https://kb56.tw/uber-eats-coupon/>
- <https://kb56.tw/foodpanda-coupon/>

優惠券並非由 Uber Eats 或 foodpanda 官方 API 授權提供；是讀取公開網頁／資料庫內容並整理呈現。優惠是否仍有效，以外送平台實際結帳畫面為準。

## 二、GitHub Pages 實際運作

~~~text
GitHub Actions cron（每 3 小時）
  → HTTPS GET 兩份公開 JSON
  → Node.js 驗證與正規化
  → docs/coupons.json
  → Git commit / push
  → GitHub Pages 部署 docs/
  → 使用者瀏覽器 GET ./coupons.json
  → 前端依縣市、身份、分類篩選
~~~

排程時間使用 UTC cron 17 */3 * * *，約為台灣時間每三小時的第 17 分鐘，但 GitHub 可能延遲執行。每次成功執行會更新 generatedAt 與 updated。若某一來源失敗，沿用上一份該平台快取；兩個來源都失敗時不覆蓋原資料。

GitHub Pages 只能提供靜態檔案，因此頁面不再呼叫 /api/coupons。優惠券資料會在 Actions 執行時先整理成站內 docs/coupons.json，讓使用者不必直接連線到第三方優惠券來源，也避免瀏覽器 CORS 問題。

## 三、ChatGPT Site 實際運作

~~~text
使用者瀏覽器
  → HTTPS GET /api/coupons?region=...&new=...
  → Worker 伺服器端向 JSON 與 kb56.tw 發出 HTTPS GET
  → Worker 正規化、依條件篩選
  → JSON Response 回到瀏覽器
~~~

ChatGPT Site 的 Worker 入口為 worker/index.js：

- GET / 或 GET /index.html：回傳嵌入的 HTML 頁面。
- GET /api/coupons：抓取兩個優惠券 JSON，並嘗試解析 kb56.tw 表格。
- GET /api/location?lat=...&lon=...：由 Worker 呼叫 Nominatim，回傳台灣縣市。

這個版本有後端執行環境，能集中處理快取、資料轉換、CORS 與未來的私密設定；但後端仍受平台執行額度與外部來源可用性影響。

## 四、定位資料流與協定

1. 使用者按下「自動定位」後，瀏覽器呼叫 W3C Geolocation API。
2. 瀏覽器取得緯度、經度前會要求使用者授權。
3. ChatGPT Site 將座標以 HTTPS GET 查詢 /api/location。
4. Worker 再以 HTTPS GET 呼叫 OpenStreetMap Nominatim reverse geocoding，指定 format=jsonv2 與 accept-language=zh-TW。
5. GitHub Pages 版本直接由瀏覽器呼叫 Nominatim，再以回傳的 city、county、state 或 town 對照台灣縣市。

座標只用於當次反查，不寫入優惠券快取。使用者拒絕定位時仍可手動選擇縣市。

## 五、協定與格式

| 連線 | 協定／格式 | 用途 |
|---|---|---|
| GitHub Actions → raw.githubusercontent.com | HTTPS GET／JSON | 下載優惠資料 |
| ChatGPT Worker → kb56.tw | HTTPS GET／HTML | 取得表格與更新日期 |
| 瀏覽器 → GitHub Pages | HTTPS GET／HTML、JSON | 取得網站與快取 |
| 瀏覽器或 Worker → Nominatim | HTTPS GET／JSON | 座標反查縣市 |
| GitHub Actions → GitHub | Git over HTTPS／Git commit | 更新快取並觸發部署 |

## 六、失敗處理與風險

- JSON HTTP 錯誤、逾時或格式錯誤：保留上一份成功資料。
- 兩個來源同時失敗：Actions 工作流程失敗，不發布空資料。
- 外部資料可能延遲、重複、缺欄位或已過期；正規化只負責格式，不保證優惠有效。
- 開啟平台按鈕會導向 Uber Eats 或 foodpanda，優惠碼複製後仍由平台自行驗證。
- 來源網站的使用條款、頻率限制與 robots 規範必須持續遵守；不可把本專案視為官方 API。

## 七、版本差異總結

ChatGPT Site 是「請求時由後端整理」；GitHub Pages 是「排程時先整理，訪客只讀快取」。兩者共用前端介面與優惠資料欄位，但執行時機、錯誤邊界與資料新鮮度不同。

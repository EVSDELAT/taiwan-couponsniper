# 版本修改紀錄

## V1.12（2026-11-26）

- 原因：部署 log 出現 Node.js 20 棄用警告，checkout、configure-pages、upload-pages-artifact、deploy-pages 皆為舊主版本，被 GitHub 強制以 Node.js 24 執行；先升級至官方最新主版本，避免日後被淘汰。
- 項目：actions/checkout v4→v7、actions/configure-pages v5→v6、actions/upload-pages-artifact v3→v5、actions/deploy-pages v4→v5；已查證新版輸入與現有用法相容（checkout 憑證預設仍保留、enablement 與 path 輸入不變、artifact 名稱仍為 github-pages）。抓取、建置、發布重試邏輯與網站功能不變。
- 影響：消除 Node.js 20 棄用警告；upload-pages-artifact v4 起預設不含隱藏檔，本站 docs/ 無隱藏檔需求，不受影響。
- 主要檔案：.github/workflows/pages.yml、docs/02_AI交接文件.md、docs/03_專案目前狀態.md、docs/09_版本修改紀錄.md。
- 驗證：YAML 語法解析檢查通過；推送後以 GitHub Actions 部署結果確認。
- 限制：無。

## V1.11（2026-11-26）

- 原因：2026-11-24 與 2026-11-25 兩次排程部署在「發布到 Pages」步驟失敗並寄出失敗通知；查 Actions 紀錄，artifact 上傳已成功，但 deploy-pages 立即查詢 artifact 清單時 GitHub 尚未同步完成，誤判找不到 `github-pages` artifact。
- 項目：發布步驟改為最多三次嘗試，第一次失敗後等待 20 秒重試、第二次失敗後等待 40 秒再重試；三次都失敗才讓工作流程失敗。抓取、快取提交、建置與上傳步驟不變，網站功能與版面不變。
- 影響：artifact 同步延遲造成的偶發部署失敗會在同一次工作流程內自動恢復，不再寄出失敗通知；真正的部署故障仍會失敗並通知。
- 主要檔案：.github/workflows/pages.yml、docs/02_AI交接文件.md、docs/03_專案目前狀態.md、docs/05_系統架構說明.md、docs/09_版本修改紀錄.md。
- 驗證：YAML 語法解析檢查通過；2026-11-26 推送觸發之 Pages 部署成功，重試步驟於第一次發布成功時正確略過。
- 限制：若 GitHub 平台故障超過重試等待時間，該次部署仍會失敗，待下一次排程自動恢復。

- 影響：首次載入只顯示舊用戶適用的可輸入代碼優惠；新用戶、免輸碼優惠、平台資訊仍可手動切換查看。

- 驗證：Node 語法檢查；靜態建置成功；建置後頁面確認五處預設皆為舊用戶／可輸入代碼。

# 重要設計決策

## V1.07：手機優先顯示優惠券

- 使用者確認：只修改手機（580px 以下），桌面維持既有版面與配色。
- 移除手機獨立製作人資訊卡；日期與聯絡入口放入標題右側，標題下保留署名。
- 篩選集中底部面板，使用既有 DOM 與事件避免重複定位／QR Code 元件；未套用時可取消。

## V1.05：頁首資訊卡壓縮

- 決策：將製作人、聯絡／回報入口與更新日期收納在頁首右上方同一張兩列資訊卡。
- 原因：保留必要的品牌與支援入口，同時把頂端版面高度壓縮，將視覺重點留給優惠查詢區。
- 相容性：兩個聯絡按鈕仍使用既有 `data-contact` 事件，維持 LINE QR Code 彈窗；Worker 與 GitHub Pages 由同一套標記與樣式產生。
- 響應式：桌面使用固定兩列緊湊排版；手機縮小間距與字級，極窄寬度允許按鈕換行，避免水平溢出。

## V1.01：採用排程快取

- 決策：GitHub Pages 不讓每位訪客直接抓第三方優惠券，改由 Actions 每三小時產生 docs/coupons.json。
- 原因：降低 CORS、來源流量限制、重複下載及第三方暫時故障造成空白頁的風險。
- 相容性：保留 ChatGPT Site 的 Worker API；兩個版本共用同一份欄位正規化規則。
- 備援：單一來源失敗時保留該平台上一份快取，兩個來源都失敗才停止。
- 取捨：資料最多可能延遲一個排程週期，但穩定性高於逐訪客即時抓取。

## V1.08 手機密度與資訊完整性

- 依使用者確認稿採兩列頁首及獨立篩選卡片；保持原配色及桌面配置。
- 長優惠資訊預設精簡、點標題展開；不刪除來源的使用條件。融合 SVG 僅用於手機品牌區。
